# Окружение и трудности локального развёртывания

## Аппаратная конфигурация
- CPU: 12th Gen Intel Core i7-1260P (12 ядер / 16 потоков)
- RAM: 31.7 ГБ
- GPU: Intel Iris Xe (встроенная), **CUDA/NVIDIA отсутствует**
- Диск: ~720 ГБ свободно
- ОС: Windows 10/11

## Программный стек
- Python 3.12.10 (отдельно установлен, потому что `open-webui` требует `<3.13`,
  а системный Python был 3.13.5)
- Ollama 0.35.1 — инференс LLM
- LLM: `qwen2.5:3b-instruct` (1.9 ГБ, Q4)
- Эмбеддинги: `intfloat/multilingual-e5-small` (sentence-transformers, CPU)
- Векторная БД: ChromaDB 1.5.9
- LangChain 1.4.3 (`langchain-ollama`, `langchain-huggingface`, `langchain-chroma`)
- FastAPI + Uvicorn — OpenAI-совместимый шлюз
- OpenWebUI 0.11.4 — интерфейс

## Трудности и решения
1. **Нет GPU.** Инференс только на CPU. Qwen2.5-3B на этом железе выдаёт
   ответ за ~5–20 с (тёплый запуск) и 30–60 с при большом контексте.
   Модель 7B была бы заметно медленнее, поэтому выбрана 3B.
2. **`open-webui` не поддерживает Python 3.13.** Установлен отдельный
   Python 3.12 и под него создано изолированное окружение `.venv-webui`.
3. **Конфликт зависимостей.** RAG-пайплайн и OpenWebUI живут в разных venv,
   связь — по HTTP (OpenAI-совместимый API). Это заодно демонстрирует
   развязку слоёв.
4. **Первый запуск Ollama/эмбеддингов** скачивает модели (~2.5 ГБ).
   Дальше всё работает офлайн.
5. **Долгая индексация.** 400 документов → 3813 чанков, эмбеддинг на CPU
   занял ~12 минут. Кодирование запроса — доли секунды.
6. **Русскоязычный датасет.** RuLegalNER — это NER-разметка (вторая колонка
   CSV), поэтому текст очищается от разметки, а в базу идёт только сырой текст.

## Замеренная latency (top-K)
| Тип вопроса | top_k=2 | top_k=4 | top_k=8 |
|---|---|---|---|
| По базе | 31.4 с | 37.3 с | 62.5 с |
| Вне базы | 8.7 с | 5.0 с | 7.0 с |
| Конфликт | 18.4 с | 17.6 с | 37.6 с |

Рост Top-K увеличивает объём контекста и время генерации, но не улучшает
качество: для простых фактов достаточно K=2–4.
